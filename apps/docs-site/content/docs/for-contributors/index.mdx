Architecture deep dives, ADRs, patterns, testing conventions, and contributing workflow — for engineers writing Aonik itself, not operating it.

<Callout type="info">
  The rest of the docs site is written for **operators** running Aonik. This section is for **code contributors** — internal team and external collaborators making changes to the platform. The boundary matters: if a page is interesting to an operator under deadline, it belongs out there. If it explains *why* the architecture is shaped the way it is, it belongs here.
</Callout>

## What's in this section

Phase 1 of the docs rewrite ships the landing pages and the [Welcome](/docs/for-contributors/welcome) page. The detailed contributor content — architecture, ADRs, patterns, testing, database — is being rewritten from the pre-rewrite material over later phases.

In the meantime, the canonical contributor references live in the repo itself:

- **`docs/specifications/`** — design specifications kept as engineering artefacts
- **`AGENTS.md`** at the repo root — coding standards for AI agents working in the repo
- **`CLAUDE.md`** at the repo root — Claude-specific instructions
- **`CHANGELOG.md`** at the repo root — release history

The original `apps/docs-site/docs.old/` directory (preserved during this rewrite) contains the Docusaurus-era architecture, ADRs, patterns, and testing docs. Read them straight from the source tree until they land here in their new form.
