title: Prerequisites
description: The exact tools (and versions) you must have installed before running Aonik. Each item lists a check command, an install command, and a verify command.
---

This page is written for **deterministic execution** — a human or an AI agent can run every command verbatim and use the verification output to decide whether to proceed.

<Callout type="info">
  All commands assume **Windows 11 + PowerShell 7**. macOS / Linux equivalents are noted under each tool. Run every command from a regular (non-admin) shell unless a step explicitly requests **Run as Administrator**.
</Callout>

## What you will install

| Tool                  | Version       | Why Aonik needs it                                                            |
| --------------------- | ------------- | ------------------------------------------------------------------------------ |
| Git                   | any 2.40+     | Clone the repository                                                           |
| PowerShell            | 7.0 or newer  | All install commands and the Quickstart use PowerShell 7 features              |
| .NET SDK              | 10.0.100+     | Build and run `Aonik.Api`, `Aonik.Worker`, `Aonik.AppHost`                     |
| Docker Desktop        | 4.30+         | Hosts the Qdrant container that Aspire orchestrates                            |
| SQL Server LocalDB    | 2022 (16.x)   | Stores the `AonikDb` database in local development (Windows)                   |
| Node.js               | 18.18+ or 20+ | Runs the Admin UI Vite dev server                                              |

Aonik does not currently support macOS or Linux as a **primary** development environment because of the LocalDB dependency. macOS/Linux contributors run SQL Server in a container — see [Run without LocalDB (coming soon)](/docs/install-configure).

## Step 1 — Verify Windows + PowerShell 7

**Check Windows version:**

```powershell
[System.Environment]::OSVersion.Version
```

**Expected:** Major `10` and Build `22000` or higher (Windows 11). Anything older (Windows 10 22H2 / build 19045+) also works but is not the primary target.

**Check PowerShell version:**

```powershell
$PSVersionTable.PSVersion
```

**Expected:** `Major 7` or higher. If you see `Major 5`, you are in Windows PowerShell — open **PowerShell 7** (`pwsh`) instead.

**Install if missing:**

```powershell
winget install --id Microsoft.PowerShell --accept-source-agreements --accept-package-agreements
```

After install, close and reopen the shell so `pwsh` is on the PATH.

## Step 2 — Install Git

**Check:**

```powershell
git --version
```

**Expected:** `git version 2.40.0` or higher.

**Install if missing:**

```powershell
winget install --id Git.Git --accept-source-agreements --accept-package-agreements
```

**Verify after install:**

```powershell
git --version
```

**macOS:** `brew install git`. **Ubuntu/Debian:** `sudo apt-get install -y git`.

## Step 3 — Install the .NET 10 SDK

**Check:**

```powershell
dotnet --list-sdks
```

**Expected:** at least one line begins with `10.`, for example:

```
10.0.100 [C:\Program Files\dotnet\sdk]
```

If no line starts with `10.`, install.

**Install:**

```powershell
winget install --id Microsoft.DotNet.SDK.10 --accept-source-agreements --accept-package-agreements
```

**Verify after install (open a new shell first so the PATH refreshes):**

```powershell
dotnet --version
```

**Expected:** output begins with `10.0.`.

<Callout type="warn">
Aonik targets **`net10.0` exclusively**. Earlier SDKs (8, 9) installed alongside .NET 10 will not break the build, but you must not pin them in `global.json`. The repo's `global.json` already pins `10.0.100`.
</Callout>

**macOS:** Download from [dot.net/download](https://dotnet.microsoft.com/download). **Linux:** Use the [Microsoft package feed](https://learn.microsoft.com/dotnet/core/install/linux).

## Step 4 — Install Docker Desktop

Aonik's [Aspire orchestrator](/docs/install-configure/run-with-aspire) starts a Qdrant vector store as a Docker container. Docker Desktop is the supported container runtime on Windows and macOS.

**Check:**

```powershell
docker --version
```

**Expected:** `Docker version 24.0.0` or higher.

**Install if missing:**

```powershell
winget install --id Docker.DockerDesktop --accept-source-agreements --accept-package-agreements
```

The install is non-trivial — it enables WSL 2 integration, downloads the Docker engine, and prompts for a reboot on first install. **Reboot when asked**, then continue.

**After install, start Docker Desktop:**

```powershell
Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"
```

The Docker whale icon appears in the system tray. Wait until the tray menu shows **"Docker Desktop is running"** before continuing.

**Verify the daemon is reachable:**

```powershell
docker info --format '{{.ServerVersion}}'
```

**Expected:** a version number (e.g. `27.3.1`). If you instead get `error during connect: ... The system cannot find the file specified.`, Docker Desktop is installed but not running — start it from the Start menu and retry.

**Optional smoke test:**

```powershell
docker run --rm hello-world
```

**Expected:** the container prints `Hello from Docker!` and exits cleanly.

<Callout type="warn">
**WSL 2 backend is required.** Docker Desktop on Windows uses WSL 2 by default. If the installer offered Hyper-V instead, switch via **Settings → General → Use the WSL 2 based engine**. The Qdrant image Aspire pulls is Linux-only.
</Callout>

**macOS:** `brew install --cask docker`, then launch from `/Applications`. **Linux:** install Docker Engine (no Desktop needed) — `sudo apt-get install -y docker-ce` plus `sudo usermod -aG docker $USER` then re-login.

## Step 5 — Install SQL Server LocalDB

LocalDB is a developer-only SQL Server edition that ships with **SQL Server Express**. Aonik's local connection string targets `(localdb)\MSSQLLocalDB`.

**Check (two-part — installed and running):**

```powershell
sqllocaldb info
```

**Expected:** at least one line printed, for example `MSSQLLocalDB`. Empty output or `'sqllocaldb' is not recognized` means LocalDB is not installed.

```powershell
sqllocaldb info MSSQLLocalDB
```

**Expected:** a block including `State: Running`. If `State: Stopped`, run `sqllocaldb start MSSQLLocalDB`.

**Install if missing:**

```powershell
winget install --id Microsoft.SQLServer.2022.Express --accept-source-agreements --accept-package-agreements
```

During the install, accept the defaults (Basic install). The installer adds `sqllocaldb` to the PATH and creates the default `MSSQLLocalDB` instance.

**Start the instance after install:**

```powershell
sqllocaldb start MSSQLLocalDB
```

**Verify the database engine is reachable:**

```powershell
sqlcmd -S "(localdb)\MSSQLLocalDB" -Q "SELECT @@VERSION" -h -1
```

If `sqlcmd` is not on the PATH (it ships separately from LocalDB), install with:

```powershell
winget install --id Microsoft.Sqlcmd --accept-source-agreements --accept-package-agreements
```

**Expected:** output begins with `Microsoft SQL Server 2022`.

**macOS / Linux:** LocalDB is Windows-only. Run SQL Server in a container — `docker run -e 'ACCEPT_EULA=Y' -e 'MSSQL_SA_PASSWORD=YourStrong!Passw0rd' -p 1433:1433 --name aonik-sql -d mcr.microsoft.com/mssql/server:2022-latest`. You will then override Aonik's connection string — see [Connect to SQL Server (coming soon)](/docs/install-configure).

## Step 6 — Install Node.js

The Admin UI is a Vite-based React 19 app. Aspire launches its dev server when you run `Aonik.AppHost`, so Node must be on the PATH.

**Check:**

```powershell
node --version
```

**Expected:** `v18.18` or higher, or any `v20.x` / `v22.x` LTS.

**Install if missing:**

```powershell
winget install --id OpenJS.NodeJS.LTS --accept-source-agreements --accept-package-agreements
```

**Verify after install (new shell):**

```powershell
node --version
npm --version
```

Both must print a version. `npm` is bundled with Node.

**macOS:** `brew install node`. **Linux:** use `nvm` or a node distribution package.

## Step 7 — Confirm all prerequisites in one go

Run the block below as a single PowerShell script. It exits non-zero on the first failure and prints a clear ✅ / ❌ line per check — ideal for an AI agent that needs a pass/fail signal.

```powershell
$ErrorActionPreference = 'Stop'
$failures = @()

function Test-Cmd($name, $cmd, $pattern) {
  try {
    $out = Invoke-Expression $cmd 2>&1 | Out-String
    if ($out -match $pattern) {
      Write-Host "✅ $name" -ForegroundColor Green
    } else {
      Write-Host "❌ $name (no match for '$pattern')" -ForegroundColor Red
      $script:failures += $name
    }
  } catch {
    Write-Host "❌ $name ($_)" -ForegroundColor Red
    $script:failures += $name
  }
}

Test-Cmd 'PowerShell 7+'    "`$PSVersionTable.PSVersion.Major"  '^[7-9]|^[1-9][0-9]+'
Test-Cmd 'Git 2.40+'        'git --version'                     '2\.([4-9][0-9]|[5-9][0-9]|[1-9][0-9]{2})'
Test-Cmd '.NET 10 SDK'      'dotnet --list-sdks'                '^10\.'
Test-Cmd 'Docker daemon'    'docker info --format ''{{.ServerVersion}}'''  '^\d+\.\d+\.\d+'
Test-Cmd 'LocalDB running'  'sqllocaldb info MSSQLLocalDB'      'State:\s*Running'
Test-Cmd 'Node 18.18+'      'node --version'                    '^v(1[89]\.|2[0-9]\.|[3-9][0-9])'

if ($failures.Count -gt 0) {
  Write-Host ''
  Write-Host "Prerequisites failed: $($failures -join ', ')" -ForegroundColor Red
  exit 1
}
Write-Host ''
Write-Host 'All prerequisites OK. Proceed to Run with Aspire.' -ForegroundColor Green
```

**Expected:** every line prints `✅` and the final line is `All prerequisites OK. Proceed to Run with Aspire.` If any line fails, fix that prerequisite using the section above before proceeding.
