# For Contributors

:::info
Architecture deep dives, ADRs, patterns, testing conventions, and contributing workflow — for engineers writing Aonik itself, not operating it.
:::

## Why this matters

The rest of the docs site is written for **operators** running Aonik. This section is for **code contributors** — internal team and external collaborators making changes to the platform. The boundary matters: if a page is interesting to an operator under deadline, it belongs out there. If it explains *why* the architecture is shaped the way it is, it belongs here.

## What's in this section

Phase 1 of the docs rewrite ships the landing pages and the [Welcome](welcome.md) page. The detailed contributor content — architecture, ADRs, patterns, testing, database — is being rewritten from the existing material in [Legacy docs](../legacy/old-home.md) over Phase 6 of the rewrite.

For now, the canonical contributor references are:

- **[Legacy Architecture.md](../legacy/Architecture.md)** — 1,000+ lines, still accurate at the conceptual level
- **[Legacy ADRs](../legacy/decisions/README.md)** — accepted architecture decision records
- **[Legacy Testing.md](../legacy/Testing.md)** — current testing patterns and conventions
- **[Legacy contributing guides](../legacy/contributing/code-style.md)** — code style, git workflow, pull requests
- `AGENTS.md` and `CLAUDE.md` at the repo root — instructions for AI coding agents working in the repo
