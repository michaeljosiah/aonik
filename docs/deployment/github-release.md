# GitHub Release Runbook

This project uses a tag-driven GitHub release workflow.

## What is required for a release

1. Ensure `main` is green (CI/build/tests passing).
2. Confirm `CHANGELOG.md` includes release-ready notes under `Unreleased`.
3. Create and push a semantic version tag (example: `v1.3.0`).
4. Let GitHub Actions run the `Release` workflow.
5. Verify the generated GitHub Release contains:
   - autogenerated release notes
   - attached API artifact (`aonik-api-<tag>.tar.gz`)

## Release workflow behavior

The workflow in `.github/workflows/release.yml`:

- triggers on pushes to tags matching `v*` (and supports manual dispatch)
- restores, builds, and tests `Aonik.sln`
- publishes `src/Aonik.Api`
- packages the API output as `tar.gz`
- creates a GitHub Release and uploads the artifact

## Recommended release commands

```bash
# 1) make sure local main is up to date
git checkout main
git pull origin main

# 2) create annotated tag
git tag -a v1.3.0 -m "Release v1.3.0"

# 3) push tag to trigger release workflow
git push origin v1.3.0
```

## Notes

- Use stable semver tags (`vMAJOR.MINOR.PATCH`).
- If a release is cut accidentally, delete the Git tag and GitHub release, then re-tag correctly.
