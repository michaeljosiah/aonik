Delivery — the fulfilment calendar and the promise it computes

/commerce/delivery · DeliveryCalendarPage. Design of record: artboard cs-delivery (PR #268). One screen holding cause and effect: the calendar the operator edits and the earliest-delivery promise the storefront shows. The two review-hardened behaviours are load-bearing: an unsaved edit makes the committed promise visibly stale, and the no-promise state is honest, never a guess.

2 · Page structure

  1. KPI row — next delivery (from committed promise; — in the no-promise state), order cutoff (day + local time), lead days, blackout count (warn when > 0, sub-label naming the nearest date).
  2. Calendar editor card (left) — mirrors the command 1:1: a 7-button weekday toggle row (Mon-first); cutoff time input; cycle-day select (nullable — empty means the cutoff applies every day, i.e. the daily order book); lead-days number input; blackout chips (ISO dates, removable) with an add-date input; active/parked switch; footer note "Expired dates prune on save; capped at 100 future dates" and the Save button.
  3. Promise card (right, the hero) — two visual states:
    • Committed (form pristine): teal, "The storefront promises — Earliest delivery {date, formatted as a calendar date in the calendar's timezone semantics — string-formatted, never routed through the viewer's Date timezone}", plus the cutoff explanation line.
    • Stale (any unsaved edit): amber, "Unsaved changes — the promise recomputes on save", naming the still-committed date. The month grid's promise ring disappears in this state; delivery-day shading keeps previewing the edit.
  4. Month grid card — Spec 073's MonthGrid for the promise's month: delivery-day cells tinted from the edited weekday set, blackout cells struck and marked, the committed promise ringed (pristine only). Legend row. Caption explains the walk-forward rule ("a blacked-out delivery day pushes that week's orders to the next allowed date").
  5. Honest empty state strip — a dashed note card, always visible: parked calendar, no delivery days, or an unresolvable timezone all mean the public read 404s and the storefront shows no date anywhere. When the public read (fetched alongside the admin read) actually is 404, the strip upgrades to a solid warning: "Customers currently see no delivery date."

3 · Implementation instructions

  • Files: src/pages/commerce/DeliveryCalendarPage.tsx; grid from components/MonthGrid.tsx. Route + breadcrumb in commerceModule.
  • Dirty model: committed DTO in one state slot, editable draft in another; dirty = !deepEqual(draft, committed) (a small comparer in lib/calendarState.ts, unit-tested — day-order-insensitive for deliveryDays). The promise card and grid ring key off dirty; Save replaces committed with the PUT response (including the echoed promise) and clears dirty.
  • Month-grid cells derive in lib/calendarState.ts too: monthCells(promiseMonth, draftDays, blackoutDates, committedPromise, dirty) — pure and unit-tested (weekday mapping Mon-first, blackout strike, ring suppression when dirty). Date arithmetic uses UTC-safe parsing of ISO date strings (YYYY-MM-DD split, never new Date(string) through the viewer's zone).
  • Timezone field is a text input validated server-side; on 422 the field error shows the interceptor's message. Do not bundle a timezone-picker dependency.
  • No-calendar 404 on the admin read = first-run state: render the editor empty with the parked switch off and the empty-state strip solid.

4 · Acceptance

  1. Toggling any weekday immediately re-shades the grid, flips the promise card to stale, and removes the ring; Save restores the committed presentation with the server-echoed promise.
  2. The promise date renders identically regardless of the viewer's OS timezone (string-formatted calendar date).
  3. With the calendar parked, the public-read strip reports that customers see no date; activating and saving flips it without a reload beyond loadData.
  4. Blackout add/remove round-trips; a blackout on the promised date, once saved, moves the echoed promise forward and the grid shows the struck cell.
  5. calendarState.ts unit tests cover the dirty comparer and month-cell derivation (including ring suppression).
