# 011.demo-seed-bill-payment

## Objective
Define a demo seed dataset that enables a full bill payment flow in the Admin UI (create order, add item, quote, validate, submit) with realistic catalog, pricing, FX, and party data.

## Background
The Admin UI bill payment form (BillPaymentOrderFormPage) requires:
- Catalog country, category, biller, and service discovery.
- Service field validation (optional) for biller account fields.
- Pricing quote with fee + FX metadata.
- Payer and receiver party context.
- Purpose code and relationship type reference data.

The backend flow uses:
- Catalog endpoints (`/catalog/*`) for biller discovery.
- Pricing quote (`/pricing/quote`) for FX + fees.
- Orders endpoints (`/orders/bill-payments` + item management + submit).
- Party creation and compliance screening when a receiver is created inline.

## Scope
- Tenant-scoped demo seed that can be enabled per tenant via the setup wizard.
- Seed data needed to run a full bill payment order in Draft and submit it.
- Provide deterministic IDs so the wizard can show example values.

## Non-Goals
- Creating payment intents, payouts, or ledger entries.
- Live partner routing or settlement workflows.
- AI agent behavior or proposal workflows.

## Demo Seed Data Inventory

### 1) Identity and Access
Seed or ensure access for the demo operator:
- A demo tenant (if not already created by onboarding).
- A demo role assigned to the current user with at least:
  - `Catalog.Read`
  - Admin UI access policy (`AdminUserPolicy` path assumes admin role or permissions).

### 2) Reference Data (global or tenant-scoped as implemented)
Ensure these reference items exist (CatalogSeedService already seeds most):
- Countries: `GH`, `NG`, `KE`, `UG`, `TZ`, `ZA` (Type = `Country`).
- Customer tiers: `Retail`, `SMB`, `Enterprise` (Type = `CustomerTier`).
- Relationship types: `Self`, `Mother`, `Father`, `Spouse`, `Sibling`, `Child`, `Friend`, `Business`, `Other` (Type = `RelationshipType`).
- Purpose codes: `Bills`, `Utilities`, `Education`, `Telecom`, `Other` (Type = `PurposeCode`).
- Order statuses and order item statuses (Types = `OrderStatus`, `OrderItemStatus`).

### 3) Catalog (tenant-scoped)
Create a minimal but realistic biller catalog for a single corridor.

#### Categories
- Utilities (Country = `GH`)

#### Billers
- ECG Power (Country = `GH`, Category = Utilities)
- Ghana Water (Country = `GH`, Category = Utilities)

#### Biller Services
At least one service that requires validation and one that does not.

Example services:
- ECG Prepaid Electricity
  - ServiceCode: `BILLPAY.ELECTRICITY.PREPAID`
  - Currency: `GHS`
  - MinAmount: 5
  - MaxAmount: 500
  - RequiresValidation: true
  - FieldsJson (required keys): `meterNumber`, `customerName`
  - ValidationJson: `{"validationEndpoint":"/catalog/billers/{billerId}/services/{serviceId}/validate","validationMode":"precheck"}`
- Ghana Water Postpaid
  - ServiceCode: `BILLPAY.WATER.POSTPAID`
  - Currency: `GHS`
  - MinAmount: 10
  - MaxAmount: 1000
  - RequiresValidation: false
  - FieldsJson (required keys): `accountNumber`

Notes:
- ServiceCode must start with `BILLPAY` so `/catalog/countries?capabilityType=BILLPAY` returns the country.
- `FieldsJson` must include `required: true` for keys the UI must provide.

### 4) Parties (tenant-scoped)
Seed a payer party and an optional receiver party.

Payer party (Person):
- DisplayName: `Kwame Mensah`
- CustomerTierCode: `Retail`
- Contacts: email + phone
- PersonProfile: FirstName, LastName, CountryCode = `NG`

Receiver party (Person, optional):
- DisplayName: `Ama Boateng`

- PersonProfile: CountryCode = `GH`

Relationship (optional pre-seed):
- FromPartyId: payer
- ToPartyId: receiver
- RelationshipTypeCode: `Friend`

### 5) Pricing and FX (tenant-scoped)
Provide a valid FX quote and fee policy that matches the bill payment corridor.

#### FxQuote
- BaseCurrency: `NGN`
- TargetCurrency: `GHS`
- Rate: 0.0075
- ExpiresAt: now + 24h
- Provider: `DemoRate`

#### FeePolicy
- Name: `BillPay-NG-GH-Default`
- FixedFee: 50 (NGN)
- PercentageFee: 0.015
- ConditionsJson:
  - ServiceCode: `BILLPAY.ELECTRICITY.PREPAID`
  - OriginCountry: `NG`
  - DestinationCountry: `GH`
  - OriginCurrency: `NGN`
  - DestinationCurrency: `GHS`
  - CustomerTier: `Retail`
  - MinFee: 25
  - MaxFee: 500
  - MarkupBps: 150
  - RoundingMode: `AwayFromZero`
  - FeeBreakdown:
    - `SERVICE_FEE` (Fixed)
    - `FX_MARKUP` (FxMarkup)

#### LimitsPolicy
- ScopeType: `Tenant`
- ScopeId: demo tenant id
- Currency: `NGN`
- MaxAmount: 1000000
- Period: `Daily`

Notes:
- PricingQuote rows are created by the pricing endpoint; do not pre-seed.
- Ensure the FX quote is not expired to avoid quote expiration during demo.

### 6) Compliance (runtime-generated)
- No explicit seed required. Screening checks are created when a new receiver is added.
- `ComplianceService.RequiresComplianceReviewAsync` currently returns false, so submit should succeed.

## Demo Flow (Admin UI)
Use these seeded values in the bill payment form:

1) Biller discovery
- Destination country: `GH`
- Category: `Utilities`
- Biller: `ECG Power`
- Service: `ECG Prepaid Electricity`

2) Customer and service fields
- Payer party id: `{{SeededPayerPartyId}}`
- Customer tier: leave blank or `Retail`
- Service fields:
  - meterNumber = `1234567890`
  - customerName = `Kwame Mensah`
- Run validation (must pass).

3) Amounts and funding
- Origin country: `NG`
- Origin currency: `NGN`
- Amount mode: destination
- Destination amount: 150
- Quote context: `BillPayment`
- Request quote (should return fees + FX rate).

4) Receiver and compliance
- Receiver: same as payer OR existing receiver `{{SeededReceiverPartyId}}`
- Relationship type: `Self` (same) or `Friend` (existing)
- Purpose code: `Utilities`

5) Basket actions
- Add item to basket.
- Submit order (status becomes `Submitted`).

## Seed Data Constraints
- `CatalogBillerService.ServiceCode` must match the service code used in pricing quote requests.
- `CatalogBillerService.Currency` must equal the destination currency used in pricing.
- `FeePolicy.ConditionsJson` must match the corridor, service code, and tier.
- `FxQuote.ExpiresAt` must be in the future at runtime.
- `LimitsPolicy.MaxAmount` must allow the demo amount.

## Implementation Plan
1) Add a DemoSeedService in Infrastructure to insert tenant-scoped demo data.
2) Make seeding idempotent (upsert by deterministic IDs or natural keys).
3) Extend setup wizard to trigger demo seed for the current tenant.
4) Store a marker (tenant setting or dedicated table) indicating demo seed applied.
5) Surface demo IDs in the setup wizard output for quick copy.

## Acceptance Criteria
- Admin UI can load countries, categories, billers, and services.
- Service field validation passes with seeded fields.
- Pricing quote returns with fee breakdown and FX metadata.
- Bill payment item can be added to the order.
- Order submission succeeds and returns `Submitted` (or `PendingCompliance` if policy changes).
- No ledger or payment intent is created during the demo.
