Storefront config — the tunables document, beside what the customer sees

/commerce/storefront-config · StorefrontConfigPage. Design of record: artboard cs-config (PR #268). The single document of values the frontend must never hard-code, edited on the left and rendered on the right exactly as the customer's pages consume it — the same public read, the same values.

1 · API contract

CallService methodNotes
GET /commerce/config/storefrontcommerceStorefrontService.getStorefrontConfig()StorefrontConfigDto { currency, recommendedChoiceLabel, resultsPageSize, backToTopTrigger (typed JSON object, served verbatim), delivery: { listAmount, chargedAmount }, defaultBoxSlug?, extrasCollectionSlug?, box?: { minSize, maxSize, currency, perSpacePrice?, presets: [{ size, price, badge?, blurb?, saving? }] } }. Never 404s; served with Vary: X-Tenant-Id. box null means no default bundle/plan — indistinguishable from "not yet live" by design.
PUT /commerce/admin/storefront-configupdateStorefrontConfig(cmd)UpdateStorefrontConfigCommand { recommendedChoiceLabel?, resultsPageSize?, backToTopTriggerJson?, deliveryListAmount?, deliveryChargedAmount?, defaultBoxSlug?, extrasCollectionSlug? }. Null members leave stored settings unchanged; an explicit empty string clears a tenant override back to the default — for STRING members only. The nullable numeric members (resultsPageSize, both delivery amounts) cannot bind an empty string, and extrasCollectionSlug rejects empty at validation. The form sends only touched fields, and exposes "clear override" solely on the members the wire accepts it for: recommendedChoiceLabel, backToTopTriggerJson, and defaultBoxSlug (the service accepts '' there and removes the override). extrasCollectionSlug: '' is REJECTED by slug validation — that selector gets no clear action — and the nullable numerics cannot bind '' at all; resetting those awaits backend clear flags (noted inline in the UI, not faked with sentinel values).
GET /commerce/admin/collections(reuse)Populates the extras-collection select with real slugs.
GET /commerce/admin/products?kind=Bundle(reuse)Populates the default-box select with bundle slugs.

2 · Page structure

  1. The document card (left) — one field per command member: recommended-choice label (text); results page size (number); canonical currency (read-only — it comes from Tenant.DefaultCurrency, shown so the operator knows what labels the amounts); delivery list amount and charged amount (numbers; helper "0 renders as free"); default box (select of bundle slugs, clearable); extras collection (select of collection slugs, clearable); back-to-top trigger (raw JSON textarea — the stored form is a settings string; the public document serves the parsed typed object, and the helper text says exactly that; validate JSON client-side before enabling Save). Footer note quoting the omission semantics and the Vary: X-Tenant-Id / never-404 behaviour.
  2. The preview column (right) — three cards rendered from the live public read, refetched after every save:
    • The personaliser: a mock option-chip row where the default chip carries a badge whose text is recommendedChoiceLabel — captioned "the badge text is the label configured on the left; every product page follows".
    • The order summary's delivery line: list amount struck through, charged amount rendered (or Free in success tone at 0), and a small total row demonstrating the arithmetic.
    • The size step: the embedded box presets as cards (size, price, authored saving, badge). When box is null: a dashed "no default box plan — the storefront renders no size step" note (honest, not an error).
  3. Dirty flow — edits accumulate in a touched-fields map; Save PUTs only touched members, then refetches the public read so the preview proves the change landed. Per-field "clear override" buttons exist only on recommendedChoiceLabel, backToTopTriggerJson and defaultBoxSlug, sending the empty string for that member; the extras selector and the numeric fields offer no clear action (the wire would 422 or fail binding).

3 · Implementation instructions

  • Files: src/pages/commerce/StorefrontConfigPage.tsx; components/StorefrontPreview.tsx (the three preview cards — reused nowhere else yet, but kept separate for clarity). Route + breadcrumb in commerceModule.
  • Touched-field model in lib/configForm.ts (unit-tested): buildCommand(touched, values) → UpdateStorefrontConfigCommand mapping untouched → undefined (omitted from JSON), cleared → '', touched → value. Axios serialises undefined members out — assert that in the test.
  • Amount formatting via the shared lib/money.ts with the document's currency.
  • Errors: 422 validation (page size bounds etc.) as inline formError; success toast + preview refetch.

4 · Acceptance

  1. Editing only the label sends a one-member payload; every other stored setting is untouched (verify via a second GET).
  2. "Clear override" on the label sends '' and the preview badge falls back to the platform default after refetch.
  3. Charged amount 0 renders Free in the preview; nonzero renders the amount; the struck list amount always shows.
  4. Invalid JSON in the trigger field disables Save with an inline message; valid JSON round-trips to the typed object in the preview's raw display.
  5. With no default box configured the size-step preview shows the honest empty note, not an error; clearing the default box via its clear action round-trips to that state, while the extras selector and numeric fields expose no clear action.
