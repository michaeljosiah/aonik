Box plans — size-tiered bundle pricing

/commerce/box-plans · BoxPlansPage. Design of record: artboard cs-boxplan (PR #268). The container pricing behind the storefront's size step: a formula (base + per-space) with merchandised presets that win at their size. The page's signature element is the price curve — formula versus effective price with preset overrides and marginal grow costs read straight off the chart.

1 · API contract

CallService methodNotes
GET /commerce/admin/products?kind=BundlecommerceCatalogService.listProducts({ kind: 'Bundle' })Bundle picker — a tenant can run several bundles; the page edits one plan at a time.

Active products only — a draft bundle's existing plan 404s here, so for an ACTIVE bundle 404 = no plan authored yet (an authoring state, not an error).
Dependency callout. Authoring a DRAFT bundle's plan safely needs an admin read by product id (GET /commerce/admin/products/{productId}/size-plan) — without it a hidden existing plan is indistinguishable from a missing one and the full-replace save could overwrite it blind. v1 mitigation: the bundle picker lists active bundles only, with a note that draft bundles become authorable when the admin read ships.
PUT /commerce/admin/products/{productId}/size-planupsertSizePlan(productId, cmd)UpsertBundleSizePlanCommand — full replace of formula + presets. Savings are authored display values; the UI never computes one into the payload.

2 · Page structure

  1. Header + bundle picker — PageHeader with a bundle select in actions (ACTIVE bundles only — see the dependency callout); subtitle states the two pricing rules: presets win at their size, and growing a box charges boxPrice(target) − boxPrice(current), never per-space × spaces.
  2. KPI row — size range (min–max), base price at base size, per-space price, preset count.
  3. Price curve card — the shared PriceCurve component (Spec 073): dashed formula line, solid effective line, preset dots with price labels and a saving annotation where the preset undercuts the formula. The plotted domain is the whole configured range (min..max) with derived scales and generated ticks — a preset at size 20 or the formula tail must always be in view (review finding). Below the chart, a marginal-grow strip: three tiles computing effective(b) − effective(a) for representative jumps (base→first preset, between presets, past the last preset), each showing the subtraction so the rule is legible.
  4. Formula editor card — min/max/base size, base price, per-space price, currency (read-only display of the plan currency; changing currency is a deliberate act inside the same full-replace form). Inline note: any size without a preset prices as base + (size − baseSize) × perSpace; saving is a full replace.
  5. Preset table — columns: size (mono) · price (mono) · formula-at-size (muted mono, computed client-side for comparison only) · authored saving (success tone when present, — otherwise) · badge (Pill) · blurb · sort · actions (edit/remove in-row; presets edit in place, the whole plan saves atomically). Footer caption: "Savings are display values authored here — the storefront never computes one."
  6. No-plan state — when the box-plan read 404s: dashed empty card, "No size plan authored for this bundle — the storefront shows no box section until one exists", CTA seeds the form with sensible blanks (nothing invented: all fields empty, currency defaulted from storefront config's canonical currency).

3 · Implementation instructions

  • Files: src/pages/commerce/BoxPlansPage.tsx; the curve is Spec 073's PriceCurve.tsx (hand-rolled SVG per the KpiTile precedent — recharts fights the preset-dot/dashed-overlay composition). Route + breadcrumb in commerceModule.
  • Draft-state model: the page holds a local editable copy of BoxPlanDto; every field edit updates it; the curve and marginal strip render from the draft, so the operator sees the pricing effect before saving — the same cause-and-effect philosophy as the delivery page. A "dirty" indicator on the Save button; Save PUTs the full replace, reloads, toasts.
  • Scale derivation is a pure module, unit-tested (src/pages/commerce/lib/planCurve.ts): curveModel(plan) → { sizes, xTicks, yTicks, points, presetMarkers, bounds } with y-bounds from computed min/max ±10 and x-ticks thinned to every 4th size plus preset sizes. Validation guards min ≤ base ≤ max and preset sizes within range before enabling Save (client courtesy; the server revalidates).
  • Currency display: format amounts with the plan's own currency code (a plain Intl.NumberFormat helper in lib/money.ts shared across the series) — no assumption of GBP anywhere.

4 · Acceptance

  1. The curve always spans min..max; adding a draft preset at any in-range size shows its dot and bend immediately, pre-save.
  2. Marginal tiles equal effective-price subtraction and bend around presets (e.g. a discounted mid-preset makes the following jump larger).
  3. For an active bundle, a 404 plan renders the authoring empty state; saving then produces a working plan and the storefront config's embedded box section (Spec 079's preview) reflects it after reload. Draft bundles do not appear in the picker.
  4. Savings display only when authored; the payload never contains a computed saving.
  5. planCurve.ts unit tests cover tick generation and bounds at min=max edge and a 6–30 range.
