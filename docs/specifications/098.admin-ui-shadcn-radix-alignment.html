Admin UI design alignment: shadcn/ui on Radix

The Admin UI already looks shadcn-shaped (cva, cn(), Radix, lucide), but it grew three competing primitive sets, two radius philosophies, ad-hoc z-indexes and a colour vocabulary that is half Aonik tokens, half raw Tailwind palette. This spec plans a complete, control-by-control restyle onto the shadcn/ui (Tailwind v4, "new-york") anatomy and semantic tokens, keeping Aonik's teal, its charcoal dark mode and its tabular money figures as the only brand-specific notes.

1. Summary

  • Adopt shadcn's semantic token contract (background, foreground, card, popover, primary, secondary, muted, accent, destructive, border, input, ring, chart-1..5, sidebar-*) via Tailwind v4 @theme inline. The 7,000+ existing var(--color-*) references keep working through a legacy alias layer that is deleted in the last phase.
  • One primitive set. components/ui/* becomes the only home. The parallel kit in components/layout/aonik/ (Card, Pill, KpiTile, FilterBar, PageHeader) is rebuilt as compositions of ui/*, and hand-rolled controls (custom Tabs, custom Switch, inline checkboxes in DataTable, 13 bespoke fixed inset-0 overlays, 10 files using window.confirm) are replaced.
  • Every control restyled to shadcn anatomy: 36 controls inventoried in §7, each with its target classes, variants, a11y behaviour and migration blast radius.
  • Fixes three latent bugs on the way: Radix enter/exit animations never run (no tw-animate-css), secondary text and warning text fail WCAG AA contrast, and Tabs have no arrow-key navigation.
  • Delivered in five phases, foundations first, so each PR is visually shippable and reversible.

2. The ask and the success signal

The ask: make Aonik "more aligned with clean shadcn with Radix design", going through each control to restyle it. The success signal is that a developer who knows shadcn can open any Admin UI screen and recognise every control's shape, spacing, focus behaviour and states, and that adding a new control is npx shadcn add <name> followed by zero edits beyond brand tokens.

Measurable proxies, checked by the guardrails in §11:

  • 0 hex literals in .tsx (today: ~380 across the repo's React apps, the majority in the Admin UI).
  • 0 raw Tailwind palette colours (bg-gray-100, text-red-600…) in Admin UI source (today: ~420).
  • 0 window.confirm calls (today: 10 files), 0 bespoke overlays outside ui/ (today: 11).
  • Radius values drawn only from the token scale (today: 10 distinct radii including rounded-[2px], rounded-[4px], rounded-[10px], rounded-none).
  • axe-core pass on the kitchen-sink route in both themes.

3.3 Tokens and global CSS

  • index.css (804 lines) defines ~110 --color-* tokens in @theme and overrides them under [data-theme="dark"]. Dark mode redefines the gray scale inverted (--color-gray-50 becomes the darkest), so bg-gray-100 means different things per theme, a trap for any shadcn component dropped in.
  • --color-brand-primary is the same #055a60 in dark mode: teal on charcoal at 2.1:1, below the 3:1 non-text minimum for focus indicators and filled controls.
  • --color-text-secondary: #888888 on white is 3.5:1, failing AA for body text. --color-warning: #ebc334 used as text on its own 12% tint is ~1.6:1.
  • Radius tokens: sm 2px, md 8px, lg 8px, xl 12px; md and lg are identical, so the scale has no middle.
  • animate-in, fade-in-0, zoom-in-95, slide-in-from-* appear in Dialog, Sheet, Popover, Select, HoverCard and Tooltip, but neither tailwindcss-animate nor tw-animate-css is installed. Every Radix overlay opens and closes with no motion today.
  • z-index is ad hoc: 100 (overlay), 110 (dialog), 130 (popover/select), 140 (hover-card), 9999 (tooltip).

4. Design direction

The brief pins the visual language: clean shadcn on Radix. The design work is therefore not inventing a new look but deciding where Aonik is allowed to differ from stock shadcn. The answer is: in three places, and nowhere else.

  1. Teal is the only chromatic colour in chrome. Primary actions, the focus ring, selected nav and chart series 1 are teal. Everything else in the frame is neutral. Status colours appear only on status (badges, alerts, deltas), never as decoration.
  2. Money reads as money. Amounts, IDs, dates-in-tables and confidence scores are set in JetBrains Mono with tabular-nums, right-aligned in tables. This is the one typographic flourish; it earns its place because Aonik is a ledger platform and column alignment of figures is the job.
  3. Charcoal dark mode. shadcn's neutral dark is near-black; Aonik keeps the existing charcoal surfaces (#1a1d21 to #2a2e34), with a lifted teal so filled controls clear 3:1.

Everything else is deliberately stock: shadcn heights (h-9 controls, h-8 small), rounded-md controls inside rounded-xl cards, a 3px translucent focus ring, a single shadow-xs on controls and cards, bg-foreground tooltips, and sentence-case labels. Stock is the point: the value is recognisability and the ability to pull components from the registry unmodified.

4.1 Review against the brief

What the first draft did and what changed:

  • Draft kept the uppercase eyebrow above every page title because the current PageHeader and the aonik-design skill use one. shadcn pages don't, and an eyebrow repeated on every screen carries no information that the breadcrumb and sidebar selection don't already give. Revised: eyebrow removed; breadcrumb carries location (D6).
  • Draft set page titles in Infra. Two display faces in chrome dilutes shadcn's single-family calm. Revised: Infra is for the logo and auth/landing moments only; page titles are DM Sans 600.
  • Draft kept a coloured tint behind the active sidebar item (teal 12%). shadcn's sidebar uses a neutral sidebar-accent with foreground text. Revised: neutral fill, teal only on the icon of the active item, which keeps teal meaning "you are here" without painting the rail.
  • Draft used a gradient sparkline fill in KpiTile. Decoration, not data. Revised: 1.5px line, no fill.

Why dark fills carry dark text. The audit found brand teal used as text 260 times and as a fill 104 times, and the status colours used as text roughly 90% of the time (e.g. --color-error: 208 text, 7 fill). So in dark mode the solids are tuned to read as text on charcoal (4.5:1 or better), and filled controls carry dark foreground text, as shadcn's own dark theme does. P0 moved the 42 class strings that paired a teal fill with text-white onto text-primary-foreground.
Note. Hex values are shown for review. Implementation may express them in oklch() to match upstream shadcn, provided the rendered colours and contrast ratios are unchanged. Every foreground/background pair is checked in P0 (text 4.5:1, non-text 3:1).

9. Migration strategy

  1. Tokens before components. P0 changes how every existing class resolves (via aliases) without touching call sites, so the whole app shifts to the new neutrals, radius and focus in one reviewable PR.
  2. Primitives keep their public API. Where a primitive is rebuilt (Tabs, Switch, Sheet, Breadcrumb, InputGroup), the existing props keep working; new capability is additive. Call-site churn is concentrated in P3.
  3. Registry first, brand second. Pull via npx shadcn@latest add, commit the untouched file, then commit brand deltas separately so shadcn diff stays meaningful.
  4. Module-by-module page sweep. P3 PRs are cut by module folder (pages/orders, pages/ledger, …) so parallel sessions don't collide. Check gh pr list for overlapping UI PRs before opening one.
  5. Aliases die last. P4 deletes the --color-* alias block and legacy CSS classes only after the guardrail grep reports zero references.

11. Guardrails

  • An ESLint rule (no-restricted-syntax on JSX attribute strings) or a small script in npm run lint that fails on: hex literals in className/style; (bg|text|border|ring)-(gray|slate|zinc|red|green|blue|amber|emerald|yellow)-\d+; rounded-\[ and rounded-none; window.confirm; raw <select>, <table>, type="checkbox" outside components/ui; z-\[.
  • Warn-only from P1 with a per-folder baseline; error once each folder is swept.
  • A components/ui/README.md naming which primitive to use for which job (Dialog vs Sheet vs AlertDialog; Select vs Combobox vs NativeSelect; Card vs bordered section).

13. Acceptance criteria

  1. Every control in §7 is implemented to its target, or explicitly deferred in §15 with a reason.
  2. components/ui is the only primitive layer; components.json exists and npx shadcn diff reports only intentional brand deltas.
  3. Guardrail counts in §2 are zero and enforced in CI.
  4. All text pairs meet WCAG AA (4.5:1) and all focus indicators and filled controls meet 3:1, in both themes.
  5. Every Radix overlay animates in and out, and none animate under prefers-reduced-motion.
  6. No page uses window.confirm; every destructive action goes through AlertDialog with a verb-named confirm button.
  7. Money amounts and IDs in tables are right-aligned, mono and tabular across all modules.
  8. The aonik-design skill reflects the new rules.
