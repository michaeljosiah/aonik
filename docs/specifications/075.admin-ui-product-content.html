Product content — declarations, review queue and coverage

/commerce/content · ProductContentPage. Design of record: artboard cs-content (PR #268). Option-dependent declarations — figures, ingredients, allergens, usage/heating steps — rendered exactly as the customer reads them, with Spec 067's safety model as the page's spine: figures may fall back captioned; declarations are exact-authored or withheld, never substituted.

2 · Page structure

  1. KPI row — products published (active products whose block serves figures — review and declarations-withheld states count, drafts leave the denominator; review finding, round 3), combination variants, coverage gaps, awaiting review (warn tone).
  2. Review queue card — every product with requiresReview: row of product, reason, Open (selects it below) and Confirm review (POST + reload). While flagged, the copy states declarations serve withheld and figures serve captioned. If an agent surface later proposes confirmations it uses ProposalCard (coral is reserved for agent-apply); this spec ships the queue without agent integration.
  3. Product rail + workbench — left rail lists active products with a state pill: Authored (success) / Review (warning) / Withheld (muted, meaning declarations absent while figures serve). Right, the workbench renders the customer-facing label for the selected product:
    • No block at all (the raw admin read returns nothing): a dashed empty state — "Nothing published; the product page shows its explicit not-yet-published state" — with an "Author the default block" CTA. This state means no block exists, not "no figures": a block whose figures are all null still renders the workbench with — cells and its authored declarations.
    • Figure grid: seven cells (Energy/Protein/Carbs/Fat/Fibre/Sugars/Salt), mono values, — for null (never 0).
    • Ingredients / Allergens cells, each with three states: authored text; review → amber italic "Withheld while under review"; absent → muted italic "Not yet published — exact-authored or absent, never substituted".
    • Heating/usage steps: authored list of {method, body}; in the review state the section renders the withheld notice instead of steps (round-1 finding — heating withholds exactly like the other declarations).
  4. Variants + coverage cards — variants table (selection, active, edit/retire — the shipped variant contract has no note field; do not render one) with an "Author a combination" Sheet (same field set as the block, plus the selection built from the product's effective groups via 074's data); coverage card listing single-choice gaps with an "Author" shortcut that pre-fills the Sheet's selection.

3 · Implementation instructions

  • Files: src/pages/commerce/ProductContentPage.tsx; components/ContentWorkbench.tsx (the label card — reused by 082's product editor preview), components/ContentVariantSheet.tsx. Route + breadcrumb in commerceModule.
  • State derivation is one mapper, unit-tested (src/pages/commerce/lib/contentState.ts): deriveContentState(block) → 'none' | 'authored' | 'review' | 'withheld' with the precedence no BLOCK → none (the raw read returned nothing), requiresReview → review, declarations null → withheld, else authored. A declarations-only block with all seven figures null is still a block — it must never map to none, because the resolver can be serving its customer-visible safety content. The published KPI's figure-serving test is a separate measure from this mapper.
  • Forms: the block/variant Sheet uses number inputs that distinguish empty (null) from 0 — an empty field must POST null. Heating steps as an add/remove row list serialised to heatingJson.
  • Data: the rail loads the paged product list + per-product coverage lazily (fetch coverage for the selected product only); review queue derives from the product list's content flags. Errors and toasts per the house pattern.

4 · Acceptance

  1. A product with figures but null declarations renders the figure grid with both declaration cells in the absent state — never the nothing-published empty state.
  2. A product under review withholds ingredients, allergens and heating, shows the amber banner, and Confirm review restores authored rendering after reload.
  3. An empty nutrition input round-trips as null (the reload shows —, not 0).
  4. The published KPI counts figure-serving active products; a draft product changes neither numerator nor denominator.
  5. Coverage gaps offer pre-filled variant authoring; an excluded choice never appears as a gap.
