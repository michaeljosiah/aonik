Personalisation — option groups, defaults and per-product narrowing

/commerce/personalisation · PersonalisationPage in src/pages/commerce/. Design of record: starterkit artboard cs-options (PR #268). The tenant's option catalogue, its recommended defaults, and each product's narrowing of it — including the two behaviours the design review hardened: prices are absolute, deltas are derived, and a default move is a consequence surface.

1 · API contract

Every update therefore carries the full current text state and changes only what the operator touched; Retire/Reactivate sends { label: current, isActive }.

Null allowed-keys = every active choice. An empty list makes the product non-personalisable. Concurrency losers get 409 concurrency_conflict.

Raw narrowing readgetProductOptionGroups(productId)
Dependency callout. No shipped read returns the STORED ProductOptionGroupLine values — AdminProductDetailDto.effectiveOptionGroups is the resolved intersection and loses whether allowedChoiceKeys was null (inherit every active choice, including future ones) or an explicit list. Editing through the resolved view would silently convert inherited-null into a pinned list. Required: GET /commerce/admin/products/{productId}/option-groups returning the raw lines. The narrowing Sheet and table gate on it; until it ships they render read-only effective offers with editing disabled and this reason shown.

2 · Page structure (mirror the artboard)

  1. Header — PageHeader: eyebrow Commerce, title Personalisation, subtitle stating the delta rule and that the storefront's default label (e.g. "Abby's choice") comes from config — render the live label fetched from GET /commerce/config/storefront (recommendedChoiceLabel) in the subtitle, never a literal.
  2. KPI row (four KpiTiles): option groups, total choices, products narrowed (of active products), unit surcharges set.
  3. Group rail + detail — left: selectable group cards (label, choice count, current default with a star). Right: the selected group's choices table with columns default-star · choice (label + note + config-label badge on the default) · vs default · status · actions. The vs default cell renders SignedAmount(choice.price − defaultChoice.price); a footer line states "Stored prices are absolute (066 §8) — deltas derive against the default." Row actions: Edit (Sheet), Make default (opens the consequence dialog), Retire/Reactivate.
  4. Consequence dialog (the page's signature moment) — "Make default" opens a Dialog: confirm copy names old → new; on success it renders affectedProductSlugs as chips with the explanation that these products' standard combination changed and their content blocks are now flagged for review (Spec 067), plus a link-out button to /commerce/content. Products that pin their own defaultChoiceKey are absent from the report by definition — the dialog copy must not imply "all products offering the group".
  5. Per-product narrowing table — active products with columns product · offers (group chips; "Not personalisable — panel hidden" when empty) · unit surcharge (mono) · edit. Row click opens the narrowing Sheet.
  6. Narrowing Sheet (size: 'md') — built from the RAW lines: one section per catalogue group with an include-checkbox; when included, an "All active choices (inherited)" toggle representing allowedChoiceKeys: null — while on, newly added catalogue choices flow to the product automatically and the chips render read-only-solid; switching it off pins the current set as an explicit list the operator then edits chip-by-chip (included solid with SignedAmount deltas against the effective default, excluded dashed/struck), the effective default starred. Saving preserves null-vs-explicit exactly as displayed. The effective default is line.defaultChoiceKey ?? group default; the delta baseline is the effective default's absolute price — a product-level override moves the zero point (review finding, round 2). Below the groups: the surcharge input. Footer: "Save offer" performs the full replace with exactly the visible intersection — the caption says so, because a save modelled on anything less silently widens the product.

3 · Implementation instructions

  • Files: src/pages/commerce/PersonalisationPage.tsx; sub-components components/NarrowingSheet.tsx, components/DefaultMoveDialog.tsx. Register the route in commerceModule.routes; breadcrumb Commerce / Personalisation.
  • Data: single loadData fetching groups + product page + storefront config concurrently (Promise.all); requestIdRef guard; mutations re-await loadData(). Types in src/types/commerce.ts: OptionGroupDto, OptionChoiceDto, RecommendedDefaultChangeResult, ProductOptionGroupLine.
  • Delta derivation is one function, unit-tested: choiceDelta(choice, effectiveDefaultChoice) in src/pages/commerce/lib/optionPricing.ts — used by both the table and the Sheet so the two can never disagree.
  • Errors: inline banner from err.userMessage; 409 concurrency on the narrowing replace shows the banner plus a Reload button (the loser revalidates, per the backend contract). Successful writes: toast.success.
  • Empty states: no groups yet → DataTable empty state with a "New group" CTA; a group with all choices retired shows a warning pill on its rail card (the backend rejects deactivating a group's recommended default — surface that message verbatim).

4 · Out of scope

  • Selection-quote preview (066's public quote endpoint) — a future enhancement, not needed to author.
  • Multi-select authoring UX beyond what selectionMode exposes today.

5 · Acceptance

  1. A group whose default choice has a nonzero absolute price displays that choice as included and every other choice as the correct signed difference, in both the table and the Sheet.
  2. Moving a recommended default shows the affected-product chips returned by the API (and none when the API reports none), with the review link-out.
  3. The narrowing Sheet round-trips: what it displays after save equals what a fresh load renders (full-replace fidelity, excluded chips stay excluded).
  4. The default badge text equals recommendedChoiceLabel from config; changing the setting and reloading changes the badge with no code change.
  5. tsc -b clean; both themes; amounts mono right-aligned.
