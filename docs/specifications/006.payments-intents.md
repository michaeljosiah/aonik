# 006.payments-intents

## Objective
Implement payment intent and confirmation endpoints for checkout flows.

## Scope
- `POST /payments/intents`
- `GET /payments/intents/{paymentIntentId}`
- `POST /payments/confirm`

## Requirements
- Payment intent returns `paymentIntentId`, `clientSecret`, status, and redirect URL.
- Intent creation accepts paymentMethodId, returnUrl, metadata, and customer details.
- Payment confirmation accepts orderId + paymentReference + status.
- Payments execute intent; ledger entries are created server-side only.

## Application Services
- PaymentIntentService.CreateAsync
- PaymentIntentService.GetAsync
- PaymentService.ConfirmAsync

## Acceptance Criteria
- Payment confirmation does not accept raw payment DTOs.
- Payment intent supports 3DS redirect flow.
- Payment status updates are persisted and auditable.
