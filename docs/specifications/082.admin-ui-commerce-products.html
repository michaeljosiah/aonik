Commerce products — catalog list and editor with the Storefront tab

/commerce/products (+ /commerce/products/:productId) · CommerceProductsPage. The live app has no commerce catalog at all, so the host page the starterkit's "Storefront tab" update assumed must be built with it. This spec scopes the products surface to what storefront administration needs — list, core editor, and the Storefront tab — with full Spec 042 parity (variant/pricing/bundle-slot authoring) explicitly out of scope for v1.

1 · API contract

Reads expose the parsed searchKeywords: string[] on the admin detail; a mismatch here loses edits silently.

2 · Page structure

  1. List — PageHeader + KPI row (products, active, drafts, bundles) + FilterBar (All/Simple/Variant/Bundle tabs + status filter + search) + DataTable: product (hero thumb + name + slug mono) · kind · status pill · variants (mono) · tags · surcharge marker (a dot/pill indicating one exists — the summary DTO carries no surcharge currency and no timestamps, so neither a formatted amount nor an updated column can render truthfully; the amount with its currency shows in the editor). Row click opens the editor.
  2. Editor — a Sheet size:'lg' (route-addressable via /commerce/products/:productId so deep links open it) with the underline tab strip: Details · Media · Storefront.
    • Details: name, slug (immutable display after create), description, status, category, tags editor, attributes JSON editor (validated client-side; helper: "the attribute contract facet groups match on — paths traverse from this JSON's root").
    • Media: ordered thumbnails with reorder + remove + add-by-URL; Save issues the full replace in display order — array position is authoritative, no sort field exists on the wire.
    • Storefront (the PR #268 design): (1) Search keywords chip editor, helper "matched by storefront search — never serialized publicly; admin-eyes-only by API design"; (2) Storefront attributes read-back grid of the parsed attributes JSON (or the honest "no storefront attributes authored — matches no attribute facet" note); (3) Unit surcharge — amount input PLUS a currency select (defaulted to the storefront config's canonical currency, which the tab fetches): the service rejects a non-null amount with a blank currency, and a product without a surcharge has both fields null, so first-time creation must supply the pair; clearing sends null amount. Helper: "the one price-like field a product card may show"; (4) Deep surfaces — three status rows read from the selected product's real state: Personalisation (n groups offered / not personalisable), Product content (authored·variants / not authored — honest empty state), Size plan (bundles only). Each with an Open link-out to 074/075/076's pages. Statuses always describe this product — never another product's data (the round-1 review finding that shaped this tab).

3 · Implementation instructions

  • Files: src/pages/commerce/CommerceProductsPage.tsx; components/ProductEditorSheet.tsx with tabs/DetailsTab.tsx, tabs/MediaTab.tsx, tabs/StorefrontTab.tsx. Routes (list + isDynamic detail) + breadcrumbs in commerceModule.
  • Touched-field PATCH reuses the 079 pattern (lib/configForm.ts-style builder, unit-tested) — an untouched member never appears in the payload.
  • Keywords editor: chips add/remove bound to searchKeywords from the admin detail; when touched, PATCH sends searchKeywordsJson: JSON.stringify(array) — the array member does not exist on the write contract.
  • Deep-surface fetches run lazily when the Storefront tab first opens (three parallel calls, individually error-tolerant — a failed status row shows "unavailable", not a broken tab).
  • Route-addressable Sheet: the list page reads :productId from params; open/close syncs with router navigation so Electron/hash routing works.

4 · Out of scope (v1)

  • Variant CRUD, per-variant pricing windows, bundle slot authoring, category-tree management, inventory — Spec 042-scope surfaces to be specified when needed; the DTOs render read-only summaries where they appear.

5 · Acceptance

  1. Opening any product shows ITS keywords/attributes/surcharge/deep-surface statuses; switching products swaps every field (no leakage between products).
  2. Editing only the name PATCHes one member; keywords untouched survive (verified by re-GET).
  3. The Storefront tab's three status rows link to 074/075/076 and reflect reality (a bundle without a plan says so; a non-bundle says "not a bundle").
  4. Summary rows never render a retail price or a fabricated timestamp; surcharge amounts render only in the editor where the currency is known.
  5. Deep link /commerce/products/{id} opens the editor directly; close returns to the list URL.
