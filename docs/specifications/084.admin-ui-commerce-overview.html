Commerce overview — the storefront's pulse and its attention row

/commerce · CommerceOverviewPage — the section landing. Design of record: the overview attention-row update (PR #268), grown into the page the live app never had. Its job is triage: four numbers, recent orders, and an attention list where every row is a real state read from the owning surface with a link-out — never a computed guess.

1 · Data sources (all shipped except where 083's callouts apply)

Tile / rowSource
Orders · revenue (paid) · AOV · awaiting fulfilmentGET /orders?orderType=ProductPurchase (existing spine list) aggregated client-side over the loaded window, per currency — rows carry their own currency, and summing across currencies fabricates a number. Single-currency windows render plainly; mixed windows render the dominant currency's aggregate with a "+ n orders in other currencies" note (the Spec 081 rule). The caption names the window honestly (e.g. "latest 100 orders") rather than implying all-time. Payment-status-dependent tiles (paid revenue, awaiting fulfilment) additionally gate on Spec 083's list projection; until it ships they render as count-only tiles.
Content awaiting review074/075's product list content flags (requiresReview count). Links to /commerce/content.
Delivery promise stateGET /commerce/config/delivery — live date (info tone) or "no promise — customers see no date" (warn tone) on 404. Links to /commerce/delivery.
Drafts staged in collectionsAdmin collections membership (Spec 078 data) — count of draft members. Links to /commerce/merchandising.
Unpriceable extras skippedGET /commerce/catalog/extras → skipped when > 0. Links to /commerce/merchandising.
Abandoned / drift-blocked cartsBehind 083's carts admin endpoint — the rows render only when that dependency ships; absent, they are omitted (not zeroed).

2 · Page structure

  1. KPI row — the four order tiles (KpiTile, mono values).
  2. Recent orders card — last N ProductPurchase orders (id mono · buyer · total mono · status pill · date), row-click navigating to /commerce/orders/:orderId — the route-addressable drawer Spec 083 defines.
  3. Needs attention card — the storefront pulse rows above, each: icon · statement · sub-line · link-out chevron. Tones: warn for review/skipped/no-promise, info for a live promise, muted for drafts. A row with nothing to report is omitted entirely — an empty attention card renders "All quiet on the storefront."

3 · Implementation instructions

  • Files: src/pages/commerce/CommerceOverviewPage.tsx; attention rows as a local AttentionRow list component. Route /commerce + breadcrumb Commerce in commerceModule; the nav parent's own href lands here.
  • Loading: the sources start together but settle independently — each request updates its own state slot in its own .then/.catch (no joint await Promise.allSettled, which would hold every card hostage to the slowest source); a failed source renders its row in a degraded "unavailable" state rather than sinking the page.
  • No invented aggregates: every number is either an API count or an aggregation over data actually loaded, with the window named. Nothing extrapolates.
  • Both themes; numbers mono; link-outs are router navigations.

4 · Acceptance

  1. With review items, staged drafts and a skipped extra present, the attention card lists each with the right tone and working link-outs; resolving them (via the owning pages) empties the card to "All quiet".
  2. The no-promise state renders the warn row; an active calendar renders the live date row.
  3. A failing source degrades only its own row/tile.
  4. Order tiles match the loaded window's arithmetic per currency — a mixed-currency window never renders a single cross-currency total — and the caption names the window.
  5. tsc -b clean; both themes.
