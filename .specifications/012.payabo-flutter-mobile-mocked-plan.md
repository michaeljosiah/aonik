# 012.payabo-flutter-mobile-mocked-plan

## Objective
Build a Flutter mobile app for Payabo with visual and flow parity to the HTML design system in `apps/website/mobile`, starting with mocked data and mocked integrations before wiring to live APIs.

## Source of Truth
- UI screens and flow references: `apps/website/mobile/*.html`
- Design tokens and component styling: `apps/website/mobile/css/style.css`
- Interaction behavior patterns: `apps/website/mobile/js/script.js`
- Existing Payabo flow and API contract references:
  - `apps/Payabo/src/app/routes.tsx`
  - `apps/Payabo/src/api/catalog.ts`
  - `apps/Payabo/src/api/orders.ts`
  - `apps/Payabo/src/api/payments.ts`
  - `apps/Payabo/src/api/profile.ts`
  - `apps/Payabo/src/api/dashboard.ts`

## Delivery Strategy (Mocked First)
1. Lock UI parity first with deterministic mock data and mock state transitions.
2. Keep repository interfaces API-ready so mock implementations can be swapped with live services later.
3. Preserve domain semantics in app flow:
   - Order draft first (business intent)
   - Payment intent second (payment execution)
   - Status polling for final outcome
